# Flow

Design screens as steps on a path, each shaped by the ones around it.

- Ask how the user arrived at each screen and what they most likely do next, and make that next step one action away. Chain small decisions (pick a template -> add people -> send) so each step feels like the obvious move.
- Move complexity into the system (Tesler's law). Some complexity can't be removed, only moved. A date field that accepts typing and opens a calendar beats three dropdowns, and a pasted address that splits itself replaces five fields.
- Link every object you show. When a task shows its project and its assignee, both open their own pages, and hovering shows a preview card with what matters from here. If an object is reachable only from the sidebar, links are missing.
- Give each screen one job. Home may summarize; anywhere else, more needs mean a new page or a sheet, not a denser layout.
- Onboard by making the first real thing. Ask what they're here to do, branch on it (solo vs team), build their first project with them, and say that every choice can change later. Values: `references/components.md` (Onboarding).
- For a new format, start from the nearest pattern users already know (Jakob's law) and change only what the content demands.

**Check:** From each screen, is the next likely action one step away? Can every object shown be opened directly from where it appears?
