# Intent

Start from what the user came to do. The layout and the app frame follow.

- **Build the feature before the frame.** Design the working part (the invoice editor, the search form, the composer) before the nav, sidebar, header, and footer. The frame is sized to what it holds, so it comes once that is known.
- **Make the main intent's control the strongest thing on screen.** On a bike-rental site the intent is "find a bike for these dates here", so the location and dates control leads. Add surfaces only as the intent widens: browsing adds results and filters; comparing adds a compare view.
- **Let the content's purpose choose the layout.**
  - one strong claim: large, centered, alone
  - a few features: visuals lead, text supports
  - many parallel features: a grid of varied tiles
  - a process: numbered steps in order
- **Show at each level only what users scan for.** A list carries the fields people compare; everything else waits on the detail view.
- **Function before finish.** Typeface, color, and icon choices come after the structure works (**Iterate**).

**Check:** Is the control for the main intent the most prominent one? Does any part of the frame exist without content to serve?
