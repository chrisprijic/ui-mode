# Intent

Start from what the user came to do. The layout and the app frame follow.

- Design the working part first (the invoice editor, the search form, the composer), then the nav, sidebar, header, and footer. The frame is sized to what it holds, so it waits until that is known.
- Make the main intent's control the strongest thing on screen. On a bike-rental site the intent is "find a bike for these dates here", so the location and dates control leads. Add surfaces only as the intent widens. Browsing adds results and filters, and comparing adds a compare view.
- Let the content's purpose choose the layout:
  - one strong claim: large, centered, alone
  - a few features: visuals lead, text supports
  - many parallel features: a grid of varied tiles
  - a process: numbered steps in order
- At each level, show only what users scan for. A list carries the fields people compare, and everything else waits for the detail view.
- Typeface, color, and icon choices come after the structure works (**Iterate**).

**Check:** Is the control for the main intent the most prominent one? Does any part of the frame exist without content to serve?
