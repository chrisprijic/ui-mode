# Iterate

Structure first, detail later, in short loops on the real thing.

- **Work rough first.** Boxes, text, one gray, the system font. Typeface, shadows, icons, and color wait until the structure holds.
- **Get the ranking right in grayscale.** If the hierarchy only works with color, it doesn't work: space, size, weight, and contrast carry it first. Color goes on last and adds meaning, not order.
- **Build the smallest useful version, then use it.** Ship the core path, run it with real data, and let what you learn decide the next edge case.
- **Design only what will ship.** If a part is uncertain, design the screen without it. A slot for a maybe-feature is a promise; an empty "Coming soon" tab is a **tell**.
- **Explore wide before narrowing.** Sketch two or three distinct directions, and look at competitors and neighbouring products, before you commit to one.
- **Run two quick tests.**
  - Structure test: replace the content with gray bars. The layout should still read.
  - Glance test: look for five seconds. You should be able to say what the screen is for and what to do next.

**Check:** Does the grayscale version already rank correctly? Does anything promise a feature that isn't built?
